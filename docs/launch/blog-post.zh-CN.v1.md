# 我为什么做了 CiteDuo：不只是找到论文，而是把论文之间的关系讲清楚

读论文有一个很容易被低估的动作：**找到下一篇该读什么**。

一篇论文读到一半，作者提到一个熟悉的方向。顺着参考文献点进去，看到另一篇论文，觉得它们大概有关；再搜几篇，浏览器里很快就开出十几个标签页。过了一会儿，我通常会遇到两个问题：

1. 这篇论文附近还有哪些值得看的工作？
2. 我手上这两篇论文，到底是什么关系？

第一个问题已经有不少工具做得很好。第二个问题却没有那么容易回答。

你可以看到一张漂亮的引文网络图，也可以看到两篇论文出现在同一个推荐列表里，但这并不等于知道它们为什么相关。它们可能直接引用了对方，可能共同引用了一批早期工作，也可能只是摘要里用了相似的词。

**我做 CiteDuo，就是从这个疑问开始的：能不能不要只画一张图，而是把两篇论文之间的连接路径找出来，并且把每一跳说清楚？**

> [CiteDuo GitHub 仓库](https://github.com/benbenlijie/citeduo) · [在线 Demo](https://watchdeep.net/paper-demo/)

## 一张图能告诉你什么，又不能告诉你什么

传统的论文探索，大多从一篇论文出发。

输入一篇论文，工具帮你展开它引用过的论文、引用它的论文、以及语义上相近的论文。这样做非常适合建立一个领域的“地图”：你能看到哪些论文聚成了一团，哪些工作是重要的中间节点，某个方向大概是怎样发展起来的。

但当你已经有了两篇论文，问题就变了。

比如，你在写综述，想确认一句“论文 B 在论文 A 的基础上改进”。这时你真正需要的不是“B 附近有哪些论文”，而是：

- A 是否真的被 B 引用过？
- 它们是不是共同引用了某篇关键工作？
- 两篇论文之间有没有一条更长但更有解释力的引用链？
- 如果没有直接的引用关系，所谓“相关”是不是只是语义相似？

图上的一条线只说明“它们被某种方式连起来了”。它没有自动告诉你，这条线究竟代表什么。

所以 CiteDuo 的重点不是再做一张更大的图，而是把“这两篇论文是怎么连上的”变成一个可以检查的答案。

## CiteDuo 的核心：给两篇论文找一条有证据的路

在 CiteDuo 里，你可以选择任意两篇论文，交给关联分析。它会尝试找出它们之间的路径，再按照关系的可靠程度排序。

一条结果可能长这样：

> 论文 A 引用了论文 C；论文 B 也引用了论文 C，因此 A 和 B 通过共同被引联系起来。

也可能是：

> 论文 A 与论文 C 共享参考文献，论文 C 又被论文 B 引用，因此两篇论文之间形成了一条文献耦合与引用混合的路径。

这里有一个我很在意的区别：**“找到了路径”不等于“证明了关系”。**

只要图足够大，几乎什么论文都能绕几步连起来。如果把直接引用、共同引用、推荐结果、向量相似都当成同一种边，最后得到的很可能只是一条看起来合理、实际上没有多少解释力的路线。

因此，CiteDuo 会把不同来源的关系分开处理：

- 直接引用：最强的证据，至少能说明论文之间存在明确的引用事实；
- 共同被引或文献耦合：说明两篇论文在引用或阅读范围上有结构性的交集；
- 相关作品推荐：可以帮你发现候选论文，但它更像是线索；
- 语义相似：适合扩大搜索范围，不应该单独拿来证明两篇论文有继承关系。

结果里不仅有排序后的路径，也会显示每一跳是什么关系，并尽量给出备选路径。这样你可以区分：这是一个很直接的引用联系，还是一条需要谨慎解读的语义桥。

## 从“找关系”开始，慢慢长成一个论文工作台

最初我只想解决两篇论文之间的关系问题。但真正用起来以后，我发现论文阅读很少是一个孤立动作。

你先搜索一篇论文，接着想看看它的引用网络；找到另一篇之后，想把两篇并排比较；确认关系以后，又想直接打开正文；正文读到某一节，又希望先翻译一下，或者问一个具体问题。

如果每一步都要在不同的网站、PDF 阅读器、翻译工具和聊天窗口之间来回切换，思路很容易被打断。于是 CiteDuo 逐渐把这些环节放到了一起。

### 1. 搜索论文，展开引用网络

CiteDuo 聚合 Semantic Scholar 和 OpenAlex 的论文信息，并按 DOI、arXiv 标识等方式归一化，尽量避免同一篇论文在图里出现多次。

打开一篇论文后，可以继续展开它的引用网络。网络图支持 2D 和 3D 视图，也可以按边的类型筛选，观察不同关系是怎样把论文连在一起的。节点的布局会被保存下来，下一次打开时不用从头再跑一遍。

这部分适合回答：

> “这篇论文所在的研究脉络，大概是什么样？”

### 2. 把两篇论文放在一起比较

当你已经有两个候选工作时，可以把它们左右并排打开，各自查看引用网络，并把这一对论文直接交给关联分析。

这比记住两个标题、来回切换标签页轻松一些，也更适合做文献综述、技术选型，或者确认一条研究脉络。

![双论文并排对比](../images/compare.png)

### 3. 在应用里读论文，而不是只看元数据

对 arXiv 论文，CiteDuo 会优先使用 HTML 正文阅读器，并提供章节大纲。没有 HTML 版本时，再回退到摘要页或 PDF。

阅读器里可以维护待读、在读、已读状态，记录阅读进度，也可以做高亮和批注。这些内容保存在自己的实例里，不需要为了保存一个笔记再登录第三方服务。

![阅读器与双语翻译](../images/reader-translation.png)

### 4. 沉浸式双语翻译

论文阅读中最容易破坏节奏的事情之一，就是读到一段难句后，复制、切换窗口、粘贴、再切回来。

CiteDuo 支持逐段翻译和双语对照，译文可以展开或折叠。翻译既可以使用配置好的 OpenAI 兼容 provider，也可以在浏览器内使用内置 Translator API 完成。

我不把它设计成“把整篇论文翻译成另一篇文章”，而是尽量让原文和译文在同一个阅读位置上出现。遇到术语不确定时，可以随时回看原文，不用在两个页面之间找来找去。

### 5. 让 AI 先读正文，再回答问题

论文问答很容易变成另一种形式的“凭印象回答”。模型知道这个领域的大概内容，却未必真的读过你眼前这篇论文。

CiteDuo 的 AI 阅读助手由本地的 `opencode` agent 驱动。回答前，它会先通过论文搜索和章节读取工具检索正文，再根据检索到的内容回答。阅读过程中可以看到它正在搜索什么、读取哪一节，而不是只收到一个突然出现的结论。

![AI 阅读助手](../images/ai-assistant.png)

这并不能保证答案永远正确，但至少把问题变得更诚实：答案应该尽量来自当前正在阅读的论文，而不是来自模型模糊的记忆。

## 为什么选择本地优先

我不太想把它做成一个“注册之后才能使用”的线上黑盒。

CiteDuo 默认是自托管、本地优先的：一个 Bun 进程，一个 SQLite 文件，不需要账号。搜索结果、论文关系、网络布局、笔记、收藏和阅读状态，都可以留在自己的机器上。

这样做不一定是所有人的最佳选择。线上服务更省事，数据规模也可能更大。但对经常读论文的人来说，本地运行有几个实际好处：

- 不需要把自己的阅读记录交给一个不确定的服务；
- 可以按自己的需求配置翻译和 AI provider；
- 缓存会随着使用积累，已经抓过的关系不必每次重新请求；
- 没有网络时，已有的本地关系仍然可以继续探索；
- 可以导出 PNG、JSON、BibTeX、CSV，或者把当前状态通过链接分享出去。

如果你只是想先看看效果，可以直接打开 [在线 Demo](https://watchdeep.net/paper-demo/)。它是一个用于试用的快照实例，限流更严格，而且没有配置 LLM，所以 AI 助手和 LLM 翻译在 Demo 中是关闭的。想完整使用功能，可以自己部署。

## 三分钟跑起来

如果机器上有 Docker，直接运行：

```bash
docker run -d --name citeduo \
  -p 8787:8787 \
  -v citeduo-data:/data \
  ghcr.io/benbenlijie/citeduo:latest
```

然后打开：

```text
http://127.0.0.1:8787
```

也可以从源码运行。项目需要 Bun 1.3+ 和 pnpm 9：

```bash
git clone https://github.com/benbenlijie/citeduo.git
cd citeduo
bash scripts/setup.sh
bun run build:web
bun run server
```

搜索功能开箱可用。如果配置 Semantic Scholar API key，上游请求通常会更顺畅；翻译和 AI 助手则可以根据自己的环境选择是否配置。

## 它不打算取代谁

Connected Papers、Litmaps、ResearchRabbit、Inciteful 等工具已经把论文邻域探索做得很成熟。CiteDuo 并不是要把这些工具都替代掉。

它更像是从另一个角度补了一块拼图：

- 其他工具更擅长回答“这篇论文周围有什么”；
- CiteDuo 更关心“我手上的这两篇论文究竟怎么联系起来”；
- 其他工具通常把你带到线上服务里；
- CiteDuo 更强调跑在自己的机器上；
- 其他工具的 AI 功能可能直接给出总结；
- CiteDuo 希望 AI 在回答之前，先对当前论文正文做检索。

如果你只想快速找几篇相似论文，CiteDuo 不一定是最短的路径。但如果你正在梳理一个研究方向，手里已经有几篇关键论文，或者经常需要确认“两篇论文之间到底是什么关系”，它可能会更顺手。

## 还有很多地方没有解决

论文数据本身并不完整。不同数据库的覆盖范围、元数据质量和限流策略都不一样。一篇论文的参考文献列表缺失时，工具再聪明也无法凭空补出一条可靠的引用关系。

语义相似也只是线索，不是证据。CiteDuo 目前给关系排序使用的是工程上的设计选择，不是经过大规模人工标注校准出来的科学结论。所以我更愿意把它当成“帮助你缩小范围、暴露线索”的工具，而不是替你完成文献判断。

AI 助手也一样。它可以帮你定位正文、解释段落、整理思路，但真正重要的判断仍然应该回到论文原文和引用上下文里。

这些限制不会消失，至少不会因为换一个更大的模型就自动消失。把它们写出来，是因为我希望使用者知道：CiteDuo 给出的不是“论文关系真相”，而是一条可以继续核查的探索路径。

## 如果你也经常读论文

这个项目现在还是一个持续迭代中的开源项目。你可以：

- 直接使用 [在线 Demo](https://watchdeep.net/paper-demo/)；
- 从 [GitHub 仓库](https://github.com/benbenlijie/citeduo) 自托管；
- 提交 issue，告诉我哪类论文关系最容易被误判；
- 提交代码，改进搜索、图谱、阅读器、翻译或 AI 助手；
- 分享你的使用场景，尤其是那些现有工具没有很好解决的场景。

我做它并不是因为论文阅读已经有一个完美答案，而是因为自己一次次在“这两篇论文应该有关，但我说不清为什么”的地方卡住。

如果 CiteDuo 能让你少开几个标签页，少在不同工具之间来回切换，并且在写下“这两篇论文相关”之前多得到一点可以核查的依据，那它就已经帮上忙了。
